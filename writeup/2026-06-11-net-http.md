# 2026-06-11 — net + http modules

## Work done

- **`modules/net`** — client-and-server socket networking on the vat/port substrate. Async TCP
  connect/listen/accept and UDP send_to/recv_from as per-op vat sources (the `port` pattern);
  established conns vend a `Mel_Stream` lowered onto `port` (the `process_pipe` shape); DNS
  resolve as blocking `getaddrinfo` on an owned worker pool (the `fs` pattern, literal hosts
  short-circuit on the loop thread); pure v4/v6 address value-type with hand-rolled parse and
  RFC 5952 formatting; house u32 status bitset with raw OS error carried alongside. posix backend
  covers macOS/iOS/Linux/Android; win32 and wasm stub `UNAVAILABLE`. 12 tests (address vectors,
  loopback TCP echo through streams, UDP round-trip, resolve, connect-refused, cancel); verified
  under Guard Malloc and across repeated runs. Spec at `modules/net/spec.md`, owed items in
  `todo.md`.
- **`modules/http`** — HTTP/1.1 client over net streams. Pure wire layer (`src/wire.c`): request
  serializer, incremental response parser (content-length, chunked incl. extensions/trailers,
  close-delimited, 1xx interim skip, 204/304/HEAD, header-block cap), vector-tested byte-by-byte.
  URL parse + percent coding in `<http/url.h>`. Fetch engine: keep-alive pool keyed by host:port
  with per-host cap, FIFO admission and idle sweep; single sanctioned retry on dead pooled conns;
  redirects (opt-in count, 301/302/303 method rewrite, https→http refused by default); response/
  total timeouts via a per-op deadline source; cancellation; collect-mode body with size cap or
  stream-to-sink with backpressure. 4xx/5xx is a successful transfer. 15 tests including loopback
  fetches against a scripted net-based server (keep-alive reuse proven by accept count); Guard
  Malloc clean. Spec at `modules/http/spec.md`, owed items in `todo.md`.
- Both specs were first iterated in `design/` against failure-mode lists, then moved into the
  modules per MEL-SPEC-002.

Notable debugging: net's drain originally gated on `wakeable.revents`, which the waiter does not
populate the way port's never-look-at-revents drains assume — switched to syscall-retry drains
and taught `connect_finish` to distinguish in-progress/connected/failed via getpeername (macOS
returns EINVAL, not ENOTCONN, on a failed connect). The TCP echo crash was the io stream-op
contract: `mel_stream_future_release` recovers a `Mel_IO_Op` `{future, result, alloc, owned}`,
and the conn stream's op record had omitted `owned` — Guard Malloc pinpointed it.

## Kludges

None knowingly left. Honest cuts are recorded as owed work in each module's `todo.md` rather than
papered over: net (win32 backend, tls, happy-eyeballs, single-in-flight accept/udp ops), http
(https, streaming request bodies, relative-redirect resolution, decompression hook, wasm fetch
lowering, per-read inactivity timeout). Two contract-shaped warts worth flagging:
- The io stream-op record layout (`future, result, alloc, owned`) is an implicit ABI between io
  and every stream implementor, enforced only by a static_assert convention. Third copy of it now
  exists (io scratch, process pipe, net conn). It wants a public `Mel_IO_Op`-shaping helper in io.
- `Mel_Net_Address.bytes[16]` and protocol-state `#define`s in http's wire layer lean on the
  MEL-CODE-001/002 protocol exceptions; called out in the specs.

## CLAUDE.md suggestions

- The io stream-op release contract (record must lead with the embedded future and mirror
  `Mel_IO_Op`) is undocumented outside a static_assert in process_pipe; if io grows a doc or the
  helper above, a one-line pointer in the io readme would have saved a heap-corruption hunt.

## Suggestions

- Promote the fd-stream-over-port shape (now in process_pipe and net's conn stream) into `io`.
- `string`'s builder.h is a stub (todos); http serializes through a raw byte array. Implementing
  the builder would clean up wire.c and future consumers.
- Next slices per the specs: `net-tls` once crypto's surface exists (unblocks https), then the
  websocket client over net+http vocabulary, and the win32 net backend (vat needs a win32 waiter
  first).
- `server` (mongoose) could eventually rebase its TLS/HTTP vocabulary on net/http types, but that
  is a separate wave; nothing was touched there.
