# GPU RHI rewrite — Milestone M1 (Vulkan, skeleton-to-triangle)

Implements M1 of `design/gpu-rhi.md`: retire the hello-triangle toy `modules/gpu`, stand up the
Tier-0 cross-cutting primitives plus the Tier-1 device foundation on the Vulkan backend (MoltenVK on
macOS), and bring the `apps/hello-gpu` triangle/cube/lorenz up on the new RHI via `--gpu=vulkan`.

## Work done

- **Retirement.** Deleted the toy `modules/gpu/{include/gpu/*.h, src/*}` (metal/vulkan/webgpu). The
  historical reference already lives in `mel_old/`. Rewrote `build.c` to a Vulkan-only backend with the
  `MEL_GPU_VULKAN` define and two test targets.
- **U1 handles** (`handle.h`): typed value handles wrapping `Mel_SlotMap_Handle`; `Owned`/`Borrowed` +
  `capture_replay` resource header; direct/`*_Indirect` family macros; per-type slotmap owned by the
  device, with leak detection at `device_destroy`.
- **U2 status** (`status.h`/`result.h`): per-action `{value,status}` results; `Mel_Gpu_Severity` in the
  low two bits; branch-free `failed/warned/ok`; failures logged at the site via `mel_log_error("gpu",…)`.
- **U3 async spine** (`future.h`, `src/future.c`): reactor-driven `Mel_Gpu_Future` + one completion pump
  per device; internal ready-queue drained by `pump_tick` (timer-driven with a coalesced cross-thread
  drain post, or manual for tests); idempotent resolve; backpressure high-water warning + 4× hard assert;
  `*_sync` wait with a reactor-thread deadlock assert; pump supports a NULL reactor (manual-tick) for tests.
- **U4 caps** (`caps.h`, `src/vulkan/caps.c`): immutable domain-structured caps probed from the physical
  device (adapter type/IDs/uuid, memory `host_visible_device_local` UMA-vs-ReBAR split, timeline tier,
  timestamp tier/period, shader numeric bits); unbuilt domains report absent honestly. Request-and-grant
  `Mel_Gpu_Feature_Request` at device-create.
- **U6 device** (`device.h`, `src/vulkan/{instance,device}.c`): explicit Instance→Adapter→Device; adapter
  enumeration + caps inspection; VK 1.2 floor + feature probes; `device_lost`/`adapter_removed` callback
  slots; headless (no surface required); `device_create_default → future`.
- **U7 queues** (`queue.h`, `src/vulkan/queue.c`): availability/acquire over the full role enum (incl.
  `SparseBinding`/`AssetIo` from day one), fallback-to-graphics with a U2 warning, `dedicated`/`priority`/
  `internally_synchronized` flags (cap-gated, locked fallback), `queue_info`, and `queue_submit → future`
  resolved by a pump poller over the submit fence.
- **U8 allocator** (`src/vulkan/memory.c`): `buddy`-backed suballocation of 64 MB `VkDeviceMemory`
  blocks per memory type (256 B min block ⇒ 256-aligned offsets), dedicated path for large/over-aligned
  allocations, UMA/ReBAR/discrete property selection, persistent map for host-visible blocks.
- **U21 debug** (`src/vulkan/debug.c`): `VK_LAYER_KHRONOS_validation` + debug-utils messenger routed to
  `mel_log` under `device.debug`; object-name plumbing in the resource header; leak detection at destroy.
- **U35 format props** (`format_props.h`, `src/vulkan/format_props.c`): `vkGetPhysicalDeviceFormatProperties`
  lowering of tiling/buffer feature bits.
- **U36 threading** (`threading.h`, `src/threading.c`): concurrency-class enum + a debug thread-safety
  tracker asserting on cross-thread misuse of `SerializedPerObject` objects.
- **Skeleton render path**: `surface.c` (+ `macos/surface.m` MoltenVK `vkCreateMetalSurfaceEXT`),
  `swapchain.c` (FIFO/MAILBOX, frames-in-flight, resize, `SRGB_NONLINEAR` format selection), `buffer.c`
  (UPLOAD direct + DEVICE staged via the allocator), `shader.c` (`shader_create_from_bytecode`, raw
  SPIR-V), `pipeline.c` (graphics pipeline, dynamic viewport/scissor Y-flip, optional push constants),
  `command.c` (frame begin/commands/end + record surface), `sync.c` (binary/timeline semaphores),
  reinstated `render_source.c` (M1 pacing stand-in).
- **Apps ported** to value-handles + Results + device-threaded calls; `gpu_host.c` to the phased device
  create.

## Kludges and debt (confessed, MEL-ENGINE-VIII)

- **U5 native interop was cut from the approved plan.** The opt-in `gpu/vulkan/<integration>.h` typed
  accessors, the inbound external-memory/semaphore import scaffolding, and the `cmd_assume_state` resync
  hook are **not implemented**. This was Phase-3 scope I dropped to reach the triangle. Owed at M1 close.
- **Skeleton render path is deliberately minimal** (sanctioned by "M1 — Skeleton"): render-pass not
  dynamic rendering; one swapchain-owned command pool, frames-in-flight = 2; binary semaphores only; empty
  pipeline descriptor layout; only the `begin/end_pass, bind_pipeline, bind_vertex/index_buffer,
  push_constants, draw, draw_indexed` subset. Full U9/U10/U12/U13/U15/U16/U17/U18 is M2.
- **Swapchain & Surface are opaque pointers, not slotmap value handles** (spec §3.1 lists swapchain as a
  handle). M1 simplification tied to the surviving `gpu_host.c` seam; convert when full U18 lands.
- **Command list is a resolved recorder pointer**, not a value handle; U15 TLS per-thread pools are not
  built. `cmd_bind_index_buffer` hardcodes `UINT16` (no index-type arg) and is untested (no app uses indices).
- **The repo slotmap is not lock-free MPMC** (spec U1 assumes it is); resource create/destroy is serialized
  by a per-device mutex — effectively `SerializedPerDevice`, not `Concurrent`. Harmless single-threaded.
- **Resource creation is synchronous `{value,status}`**; only `device_create_default` and `queue_submit`
  return futures. Spec U3 says *all* creation returns a future. The spine is built and exercised; per-
  resource async create is deferred (Vulkan creates are synchronous regardless).
- **macOS completion pump uses timer-tick + `mel_reactor_post` bridge**, not native fence-fd poll
  (MoltenVK has no fence-fd export — that is the Linux path). One of the three sanctioned primitives.
- **Residency mechanism is reported but not implemented.** `caps.memory.residency_control = budget_only`,
  but `make_resident`/`evict`/`budget_pressure` do not exist, and `memory_budget` returns the device-local
  heap size with usage 0 (no `VK_EXT_memory_budget` query). Allocator never reclaims empty blocks; the
  per-frame ring is unused.
- **Many caps are absent/stubbed**: `caps.power.*` is `unknown` (no sensor wiring — see suggestions);
  `format_props.sample_counts = 0`; no per-format MSAA / ycbcr / compression introspection.
- **The running app never destroys the device** (process lifetime); leak detection therefore runs only in
  the headless tests. `gpu_host` has no shutdown hook.
- **metal/webgpu backends removed**; on macOS (default `--gpu=metal`) `hello-gpu` builds/runs only under
  `--gpu=vulkan` until M4.
- **Validation needs `DYLD_LIBRARY_PATH=/opt/homebrew/lib`** to load the Homebrew validation dylib;
  without it the instance honestly falls back to no-validation with a warning (env setup, not an engine bug).
- **Shared-tool change**: added opt-in `MEL_TEST_NOFORK` to `tools/test/src/runner.c` (MoltenVK cannot
  survive `fork()`); env-gated, additive.
- **App test affordance**: added a `HELLO_GPU_AUTO` env hook to `apps/hello-gpu/src/main.c` to auto-open an
  app for headless render verification; left in (harmless).
- **AppKit linked on the gpu test targets** because `reactor`'s macOS backend references `NSApp` without
  publicly linking AppKit (see suggestions).
- **MEL-CODE-001 (no enums)**: the RHI uses many enums (severity, queue roles, formats, caps tiers,
  per-action statuses). Justified as protocol mappings to Vulkan/D3D12/Metal — MEL-CODE-001's own carve-out
  — and as the shape pinned by your spec and the plan you approved. Flagged per Rule #1.

## CLAUDE.md / repo-convention suggestions (recommendations only)

- **`size` is a global typedef** (`isize`) used inside `countof`→`lengthof`→`S8`→`mel_assert`. Any function
  with a parameter named `size` that also uses `mel_assert`/`S8` fails to compile with a baffling "called
  object type is not a function" error (bit me twice). Consider renaming the `size` typedef, or making
  `countof` hygienic.
- **`mel_realloc` asserts on a NULL pointer** (not realloc-from-NULL safe). A `mel_grow`/realloc-or-alloc
  helper would remove the `ptr ? realloc : alloc` boilerplate now repeated in several places.
- **`reactor`'s macOS backend should publicly link AppKit** (it references `NSApp`); today only `gui`/`app`
  pull it in, so a reactor-only consumer (e.g. a GPU test) fails to link until it adds the framework itself.
- **Document a no-fork test mode for GPU/Metal tests** (now `MEL_TEST_NOFORK`); MoltenVK cannot run in a
  forked child.

## Suggestions

- **Reconcile the `sensor` module.** §3.4/§13 of the GPU spec reference `modules/sensor/spec.md` for
  `caps.power.*` and the power/thermal events, but the repo has separate `modules/thermal` + `modules/power`
  and no `sensor`. Decide whether `sensor` is the umbrella the spec assumes, then wire `caps.power.*`.
- **Next steps**: finish M1's U5 native interop; then M2 (full resources/recording/rendering surface on
  Vulkan, D3D12 co-primary). When U18 lands, promote `Mel_Gpu_Swapchain`/`Surface` to value handles and
  introduce `design/platform-surface.md`'s `Mel_Platform_Surface`.
- **`frame.pacing`** should replace the reinstated `Mel_Gpu_Render_Source` stand-in.
