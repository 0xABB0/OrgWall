# 2026-06-03 — gpu/d3d12 hardening (verify-d3d12 audit, matrix task #12)

Branch `gpu-d3d12-harden`, two commits (`a90ea9b`, `cede43f`). Verified on win-pilot
(NVIDIA RTX 2060 SUPER, clang/MSVC, win32-debug, `--gpu=d3d12`).

## Work done

### Fix #1 — format_props.c honesty (MEL-ENGINE-VIII)
`modules/gpu/src/d3d12/format_props.c`. The cap derivation overreported.

Before:
- `LINEAR_FILTER` derived from `D3D12_FORMAT_SUPPORT1_SHADER_SAMPLE` — wrong: integer
  (`*_UINT`/`*_SINT`) and typeless formats report SHADER_SAMPLE yet are point-sampled only.
- `TRANSFER_SRC`/`TRANSFER_DST` derived from `D3D12_FORMAT_SUPPORT1_BUFFER` (typed-buffer-view
  support) — wrong: D3D12 copy is format-agnostic, independent of buffer-view typing.
- `BLIT_SRC`/`BLIT_DST` never set.

After (mirrors the Vulkan split SAMPLED vs FILTER_LINEAR in `src/vulkan/format_props.c`):
- `SAMPLED` ← `SHADER_SAMPLE` (unchanged).
- `LINEAR_FILTER` ← sampleable AND not integer/typeless. Added
  `mel_gpu__dxgi_is_integer_or_typeless(DXGI_FORMAT)`, a switch over the external DXGI enum
  (protocol mapping → MEL-CODE-001 sanctioned use) covering the UINT/SINT/TYPELESS families.
  D3D12 exposes no single "filterable" support bit; the documented rule is the typedness
  exclusion, so this conservatively withholds the cap.
- `BLIT_SRC` ← sampleable; `BLIT_DST` ← `RENDER_TARGET`. D3D12 image-to-image scaled blit is a
  sample+draw, so src needs sampling and dst needs a render target. Conservative, no overreport.
- `TRANSFER_SRC`/`TRANSFER_DST` ← format is non-`UNKNOWN` (copy is format-agnostic).
- `map_format_support` now takes the `DXGI_FORMAT` so it can classify typedness; the helper is
  file-local `static`, no external callers.

The current `Mel_Gpu_Format` set (BGRA8/RGBA8 UNORM/SRGB, RG/RGB/RGBA32_FLOAT, D32, D24S8) has
no integer/typeless members today, so on this hardware the observable cap change is the corrected
TRANSFER/BLIT bits; the integer/typeless exclusion is correct-by-construction for when the format
set grows (MEL-ENGINE-I), which is the point of the honesty fix.

### Fix #2 — silent-default test gating (MEL-CODE-007, MEL-ENGINE-VIII)
`modules/gpu/test/test_d3d12.c`. Whole TU was `#if MEL_GPU_D3D12`; on win32 the default backend
is vulkan, so a bare `nob test gpu-d3d12` compiled to an empty TU and reported `0 of 0` — green on
an untested backend. Added an `#else` branch with one loud test `d3d12_gating.backend_not_selected`
that hard-skips (`MEL_SKIP`) with a reason naming the required `nob test gpu-d3d12 --gpu=d3d12`
flag. Chose hard-skip over FAIL deliberately: a FAIL would redden every non-d3d12 configuration
(e.g. a macOS `nob test` run), which is dishonest in the other direction; the genuine state is
"this configuration cannot run d3d12 tests", the textbook skip case. The count is no longer 0, so
green-on-zero is defeated and the remedy is explicit.

### Fix #3 — status name honesty (LOW): NOT done, out-of-scope-blocked
The `MEL_GPU_*_CREATE_VK_FAILED` enumerators the d3d12 backend returns (buffer.c, texture.c,
pipeline.c, device.c) are NOT defined in `status.h`. They live in the shared per-resource public
headers (`buffer.h`, `device.h`, `texture.h`, `pipeline.h`, plus shader/query/sync/sampler/transfer)
and are consumed by the Vulkan AND Metal backends too. A clean rename to `*_CREATE_BACKEND_FAILED`
requires editing 9 non-owned headers + the vulkan/metal sources — outside my file ownership
(`src/d3d12/**`, `test_d3d12.c`, `build.c`) and beyond the status.h-only allowance the task granted.
No neutral alias exists in any header to switch the d3d12 call sites to. Minting a d3d12-local
duplicate enumerator would be a kludge (MEL-ENGINE-VIII forbids). Left the d3d12 call sites
unchanged: severity is correct (ERROR), only the name carries a vk flavor. Flagged for Gabbo as a
separate cross-cutting rename task.

### Fix #4 — Slang shader.h compatibility
Confirmed at source and on the box. The new `shader.h` keeps the legacy `spirv_vertex`/
`spirv_fragment`/`spirv` aliases; the d3d12 `shader.c` reads exactly those fields (it ignores the
new `target`/`*_blob` fields, consistent with the test feeding DXIL through the aliases). No d3d12
change needed; build + tests green against it.

### Added test
`d3d12_format.properties_honesty` (inside `#if MEL_GPU_D3D12`) — the audit noted no d3d12 test read
`format_properties`. Asserts the honesty contract on the RTX 2060 SUPER:
- RGBA8_UNORM: SAMPLED, LINEAR_FILTER, COLOR_ATTACHMENT, TRANSFER_SRC/DST, BLIT_SRC/DST set;
  DEPTH_ATTACHMENT clear; sample_counts non-zero.
- D32_FLOAT: DEPTH_ATTACHMENT + TRANSFER set; COLOR_ATTACHMENT/COLOR_BLEND clear.
- RGB32_FLOAT: buffer_features has VERTEX_BUFFER.

  `d3d12_gating.backend_not_selected` skip with the flag-naming reason. Gating verified.

Count note: baseline was 21 pass / 1 skip = 22. My added format test makes it 22 pass / 1 skip = 23
with `--gpu=d3d12`. Not a regression — one net new real test.

Iteration: first run failed `d3d12_format.properties_honesty` on `color.buffer_features == 0u` —
my own faulty assumption; RGBA8_UNORM IS a valid IA vertex format on D3D12 (reports
`IA_VERTEX_BUFFER`). Dropped that assertion (the VERTEX_BUFFER check correctly lives on the
RGB32_FLOAT case). Second run green.
