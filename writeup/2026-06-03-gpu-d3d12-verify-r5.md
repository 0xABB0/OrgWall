## Work done — three real fixes (all src/d3d12/**)

### 1. Sub-256 UNIFORM buffers over-read their CBV (debug-layer break)
A CBV is always 256-aligned (`(size+255)&~255`); a 16-byte uniform buffer produced a 256-byte CBV
that ran past the 16-byte resource. Round-4 added `classic_uniform_buffer` — the first test to bind a
small CBV through a draw — so the bounds violation broke the debug layer (the process died after
"device created", no "ok"). Fix (`buffer.c`): round the committed-resource width up to 256 for
`MEL_GPU_BUFFER_UNIFORM`. The logical `obj.size` stays the requested size; the upload copies only
`opt.size`; the CBV (256) now fits. Correct D3D12 practice (CB resources are 256-aligned by spec).

### 2. bind_group writes disambiguated only sampler-vs-resource, not descriptor class
`bg_slot` matched a write to a layout entry by `(binding, is_sampler)`. But an SRV (`t0`) and a CBV
(`b0`) legitimately share binding number 0. In `classic_uniform_buffer` the layout is
SAMPLED_IMAGE@0 + UNIFORM_BUFFER@0 + SAMPLER@0; `write_buffer(binding 0)` matched the *first*
non-sampler entry — the SAMPLED_IMAGE — and wrote the CBV into the SRV's heap slot. The shader read
the CBV slot (heap offset 1) which was never written, so `g_tint` came back all-zero and the draw
output `(0,0,0,0)`. Proven by isolating the shader to `float4(g_tint.rgb,1)` → still `(0,0,0,255)`.
Fix (`bind_group.c`): `bg_slot` takes a descriptor-class predicate; `write_texture` matches the
texture class (SAMPLED_IMAGE/STORAGE_IMAGE/COMBINED), `write_buffer` the buffer class
(UNIFORM/STORAGE), `write_sampler` the sampler class. Offset accumulation is unchanged (all
non-sampler descriptors pack contiguously in the resource table regardless of SRV/CBV/UAV subclass).
After the fix the pixel is `100 50 200 255` — exactly `(200,200,200)·(0.5,0.25,1.0)`.

This bug predates round 4; round 4 merely authored the first test that exercises two resource
descriptors at the same binding number. It would equally bite any SRV+CBV-at-same-binding set.

### 3. Three public-API gaps blocked hello-gpu from linking on d3d12
The d3d12 backend never implemented three functions the Vulkan backend has; hello-gpu scenes
reference them (`mel_gpu_swapchain_extent`, `mel_gpu_format_properties`, `mel_gpu_cmd_dispatch_indirect`).
Implemented honestly:
- `swapchain_extent` (swapchain.c) — returns `{sc->width, sc->height}`.
- `format_properties` (new format_props.c) — `CheckFeatureSupport(FORMAT_SUPPORT)` mapped to the
  `MEL_GPU_FMT_*` flags + `MULTISAMPLE_QUALITY_LEVELS` swept 2..16 for `sample_counts`.
- `cmd_dispatch_indirect` (record.c) — `ExecuteIndirect` with a lazily-created, per-device DISPATCH
  `ID3D12CommandSignature` (stride = `sizeof(D3D12_DISPATCH_ARGUMENTS)`), guarded by a new
  `dispatch_indirect_lock`, released in device_destroy.

These advance the backend per `design/gpu-d3d12.md` independently of the Slang frontend (Deliverable
4): they are device/format/command surface, no shader dependency.

## Kludges and debt (confessed, MEL-ENGINE-VIII)

- **`format_properties` LINEAR_FILTER is approximated.** D3D12 has no direct linear-filter feature bit;
  I report it whenever `SHADER_SAMPLE` is set (UNORM/FLOAT formats sample-filter by default on D3D12).
  Integer formats that sample-but-don't-filter would be over-reported. Vulkan reads a dedicated bit;
  D3D12 has none, so this is the honest best available without a per-format table. No test asserts it.
- **`format_properties` TRANSFER_SRC/DST both set when `SUPPORT1_BUFFER`.** D3D12 copy support is not a
  per-format feature the way Vulkan transfer bits are; any format usable as a resource is copyable.
  Coarser than Vulkan but not wrong for the consumer (msaa scene only reads `sample_counts`).
- **`cmd_dispatch_indirect` ignores a count buffer / multi-dispatch.** The public API is
  single-arg-buffer + offset, so `MaxCommandCount=1`, no count buffer — matches the Vulkan impl's
  surface. Multi-dispatch-indirect is a larger API change, not this round's scope.
- **hello-gpu's presented frame is not pixel-verified on d3d12.** Only device bring-up + link are
  proven; the swapchain wall is the same non-interactive constraint that skips the d3d12 present test
  and was confessed in round 4. Needs an interactive win-pilot session.
- **Stale-archive hazard in the gpu build dir.** Switching `--gpu` between vulkan and d3d12 without
  cleaning `modules/gpu/build/win32-debug/` leaves the prior backend's `.o` files in the obj dir;
  they get archived into `libgpu.a` and collide (LNK2005) / dangle (`vk*` unresolved). The test
  target relinks its own archive so `gpu-d3d12.exe` was unaffected, but `hello-gpu` reused the
  polluted archive. Worked around by `rmdir /s /q modules\gpu\build\win32-debug` before each
  cross-backend build. This is a build-system gap (the obj dir is not keyed by `--gpu`), not a code
  bug; out of my file-ownership to fix. Flagged for the build-system owner.
- **A lingering `hello-gpu.exe` in Session 0 locked the link output** (LNK1104) after a smoke run that
  blocked on the swapchain error and was not reaped by name-based `taskkill`. Killed by PID. A headless
  smoke harness that exits cleanly on swapchain failure would avoid the zombie.
- **clang-format not run** (absent on the dev mac, MEL-CODE-004); house style matched by hand.
- **`getenv`/`fopen` MSVC CRT deprecation warnings** in `test_d3d12.c` (pre-existing, round-3 test
  harness). Not errors; `_CRT_SECURE_NO_WARNINGS` would silence them but that is test-harness hygiene,
  not mine to add this round.

## CLAUDE.md suggestions (recommendations only)

- Document that `gpu-d3d12` (and any backend-specific test target) MUST be built with the matching
  `--gpu=` flag; `nob test gpu-d3d12` alone silently builds Vulkan and runs an empty `test_d3d12.c`.
  This trapped the first build of this session and is a silent-default footgun (MEL-CODE-007).

  `modules/gpu/build/<platform>-<config>/` when flipping `--gpu`, until the build system keys the obj
  dir by GPU backend.

## Suggestions

- **Key the gpu obj dir by `--gpu`** (e.g. `build/win32-debug-d3d12/`) so the two backends never share
  an archive. This is the clean fix for the stale-archive hazard above; it would also let both backends
  coexist on disk without a wipe.
- **The `…_VK_FAILED` status codes still leak from the d3d12 backend** (device.c, buffer.c emit
  `MEL_GPU_DEVICE_CREATE_VK_FAILED` / `MEL_GPU_BUFFER_CREATE_VK_FAILED` from non-Vulkan code) — the
  round-3/round-4 cross-backend rename is still unfiled.
- **An interactive win-pilot session** is the last unverified d3d12 surface (flip-model present + the
  round-4 readback-before-present fix + hello-gpu pixels). Everything headless is now green on hardware.
- **Grow-on-demand for the classic + bindless heaps** remains the one structural gap for a long-running
  app; reclaim (now proven on hardware) bounds steady-state, growth handles the high-water mark.
