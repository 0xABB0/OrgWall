### Load-bearing find — `NonUniformResourceIndex` is wrong here
The GLSL original wrote `imageStore(u_images[nonuniformEXT(root.image)], ...)`. The heap slot
rides a **push constant** — it is *uniform* across the whole dispatch, so the nonuniform
qualifier is not merely unnecessary, it is semantically wrong. Slang correctly **refuses** to
lower `NonUniformResourceIndex` for the Metal and WGSL **compute** stages
(`error E36107: unavailable features in entry point`). The committed `clear.slang` from the
prior wave has the same defect and is Vulkan-only because of it. Dropping the qualifier
(`u_images[root.image]`) makes the indexed bindless storage-image access emit cleanly to all
three targets. WGSL emits the proper unbounded `array<texture_storage_2d<rgba8unorm, read_write>>`.

## The mandelbrot-on-Metal wall (the central finding)

The proof was "mandelbrot compute renders on Metal via runtime Slang." It does **not**, and the
reason is a real, specific wall — not a tolerance gap:

Slang's stock **MSL** emit for an *unbounded* bindless resource-heap array lowers it to a
**flexible-array-member kernel parameter** (`texture2d<float, access::read_write> u_images[]`).
Metal's runtime `newLibraryWithSource` rejects this: *"flexible array members are a C99 feature."*
This is universal across resource classes — the storage-**buffer** heap emits the same way
(`uint device* u_buffers[]`). The `compute_storage_buffer` test passes on Metal only because its
MSL is **hand-authored** to the Metal RHI heap convention (`device BufSlot* storage_heap [[buffer(3)]]`),
which Slang does not auto-emit.

The Metal RHI's bindless model binds each heap class as a `device` buffer of `MTLResourceID`s at a
reserved buffer index, indexed by slot — a different binding model than Slang produces. And the gpu
module exposes **no non-bindless compute storage-texture binding** (no `setTexture` on the compute
encoder, no `cmd_bind_group`), so there is no fallback: a *single bounded* `RWTexture2D` emits clean
MSL (`texture2d<...> [[texture(0)]]`) but nothing in the RHI can bind it to a compute dispatch.

So the mandelbrot scene **skips on Metal with the precise cause** (MEL-ENGINE-VII / -VIII — degrade
honestly, do not fabricate a pass). The same kernel emits valid SPIR-V (RuntimeDescriptorArray,
proven on Vulkan) and valid WGSL. Closing the Metal gap needs a Slang→MSL bindless-heap lowering
(emit the heap in the RHI's `device X* heap [[buffer(N)]]` convention) or an MSL post-process — a
substantial change in the slang wrapper / Metal RHI, a separate lane. The Metal threadgroup fix and
the compute-from-slang plumbing are correct and in place for when that gap closes; Vulkan proves the
end-to-end compute + runtime-Slang + reflected-threadgroup pipeline.

## Kludges / out-of-fence touches (MEL-ENGINE-VIII — full account)

1. **Touched `third-party/slang/src/compile.cpp` (the slang wrapper) — OUTSIDE my file fence.**
   The raymarch fullscreen vertex shader's `SV_VertexID` was being reflected as a vertex-buffer
   attribute (format U32) with no `Mel_Gpu_Format` equivalent, so `pipeline_create_from_slang`
   loud-failed (`vertex attr 'SV_VERTEXID' (loc 0) has format 9 ...`). Root cause:
   `mel_slang__collect_vertex_attr` collected EVERY vertex-stage entry-point parameter, including
   system values. The fix skips a leaf field that has no `VaryingInput` parameter category (system
   values like SV_VertexID/SV_InstanceID carry no such category). This is the true bug site and a
   name-independent guard; slang-compile's existing `vertex_inputs` test still reflects exactly the
   3 real attrs (POSITION/COLOR/UV), so no regression. I crossed the fence because (a) the raymarch
   deliverable is impossible without it, (b) growing `format.{h,c}` would be the WRONG fix — an
   SV_VertexID is not a vertex-buffer input, so a U32 vertex format would produce a phantom attribute
   the pipeline cannot bind, and (c) the wrapper is the correct owner (slang.c could co-fix by skipping
   `SV_`-prefixed semantics, but the wrapper should not emit them as attrs at all). **Flagging for review.**

2. **Comments in test_scene.c.** I added skip-rationale comment blocks (the Metal wall, the WebGPU
   push-constant skip) matching the file's PRE-EXISTING convention (the SCENE_TOL band rationale and
   the quad WebGPU skip already carry such blocks). This is in tension with the global "never write
   comments" rule. I judged matching the immediate file's established skip-rationale pattern the lesser
   evil (MEL-SPEC-004 — future readers lack my context for why mandelbrot skips on Metal). **Flagging
   for Gabbo to rule**; trivially removable if the global rule dominates.

3. **`scene_make_device_bindless` duplicates `scene_make_device`** but for the `.features =
   { .descriptor_indexing = true }` line. The shared helper requests no features; the mandelbrot scene
   needs the heap. A `bool bindless` parameter on one helper would be cleaner, but I kept the existing
   helper untouched to avoid churning the other four scenes' call sites.

4. **App-screen mandelbrot regresses to a loud no-render on Metal/WebGPU.** With the migration, the
   Metal app screen's `pipeline_compute_create_from_slang` now loud-fails at create (the MSL wall),
   so the screen stays in its `ready=false` init-fallback. This is no WORSE than before (the original
   never bound the heap on Metal → never rendered) and now fails loudly with the MSL diagnostic rather
   than silently. Vulkan renders. Acceptable degradation, but noting it.

5. **Fixed-parameter golden frames.** Both scenes pin `time=0` (and mandelbrot a fixed center/scale/
   max_iter=256, scale=0.18) for deterministic goldens. The app screens still animate. The golden is a
   representative frame, not the animation.

## CLAUDE.md suggestions (recommendations only)
- Document that bindless resource heaps in runtime-Slang are **Vulkan/WGSL-portable but NOT
  Metal-portable** until the MSL heap-lowering lands — so screen authors do not assume a storage-image
  compute kernel renders on Metal through `from_slang`.

## Suggestions
- A cross-emit gate (compile every in-tree `.slang` × every host target, assert non-empty blob + empty
  diagnostics) would have caught BOTH the `NonUniformResourceIndex` Metal/WGSL refusal and the MSL
  flexible-array-member wall at gate time, not at pipeline-create. The #32 writeup suggested the same.
- A non-bindless compute storage-texture binding (`cmd_bind_group` on the compute encoder) would let
  storage-image compute kernels run on Metal/WebGPU without the heap, sidestepping the MSL wall for the
  single-resource case.
