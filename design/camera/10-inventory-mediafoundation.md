# mediafoundation — inventory
> api gen: Media Foundation (Win10+) + IAMCameraControl/VideoProcAmp/KSPROPERTY + WinRT MediaCapture; MFVirtualCamera (Win11 22000+) / DirectShow for publish
> covers matrix columns: win32+mediafoundation

Notation: Win32 COM interfaces `IMF*`/`IAM*`, KS driver property enums `KSPROPERTY_*`, KS property-set GUIDs `KSPROPERTYSETID_*`/`PROPSETID_*`, format GUIDs `MFVideoFormat_*`, WinRT runtime classes `Namespace.Class`. `?` marks unverified. The Win32 MF surface (SourceReader / CaptureEngine / extended-controller) and the WinRT MediaCapture surface are **two parallel app-facing stacks** over the same Frame Server + KS driver model; the inventory keeps both because they expose disjoint capability subsets (e.g. AdvancedPhotoCapture, MediaFrameSourceGroup, RegionsOfInterest are WinRT-only; IMFVirtualCamera, IMFSourceReader D3D path are Win32-only).

- **privacy indicator (Win11 cam-in-use):** OS-driven; software indicator forced via `HKLM\SOFTWARE\Microsoft\OEM\Device\Capture` DWORD `NoPhysicalCameraLED=1` when no hardware LED — source: [windowsreport](https://windowsreport.com/windows-11-camera-privacy-indicator/)
- **Group Policy:** App Privacy → "Let Windows apps access the camera" (Force Allow / Force Deny) — source: [Microsoft Learn](https://learn.microsoft.com/en-us/windows/apps/develop/camera/camera-privacy-setting)
- shutter-sound mandate — none on Windows; thermal/power throttle — no direct camera API (`..._EXTENDED_FRAMERATE_THROTTLE` / `_OPTIMIZATIONHINT` are the closest power levers)
