# Slang shader pipeline + Metal render bring-up

Design spec for U12 (§6.4 of `gpu-rhi.md`): replace the hand-compiled GLSL→SPIR-V shader path
with **Slang single-source → per-backend bundles**, and use Slang's **MSL** output to bring the
Metal backend from clear-present to actually rendering the demos.

## Why

- The demos author 37 GLSL shaders (`apps/hello-gpu/shaders/*.{vert,frag,comp}`) hand-compiled
  offline into 33 committed `*_spv.h` SPIR-V headers. There is no build step, no Slang, no codegen.
- The Metal backend cannot consume SPIR-V; `shader_create_from_bytecode` is SPIR-V-only
  (`shader.h`), pipeline/draw are stubbed. Result: Metal clears and presents but draws nothing.
- `gpu-rhi.md` §6.4 already specifies Slang as the shader frontend and `shader_create_from_bytecode`
  as accepting **MSL on Metal** / SPIR-V on Vulkan / DXIL on D3D12, with a per-backend bundle and
  Slang reflection. Slang emits all three targets from one source — the right vehicle (SPIRV-Cross
  rejected; Slang is the spec's own choice).

## Current state (grounding)

- `mel_gpu_shader_create_from_bytecode_opt(dev, { spirv_vertex, spirv_fragment, ... })` — SPIR-V only.
- `mel_gpu_shader_create_compute_from_bytecode_opt(dev, { spirv, ... })` — SPIR-V only.
- Vulkan backend reflects SPIR-V (`mel_gpu__spirv_reflect`) to derive layouts.
- Metal `pipeline.m`: `shader_create_from_bytecode` loud-errors (no SPIR-V→MSL); `pipeline_create`
  and `cmd_bind_pipeline` are loud no-ops.
- No `tools/build/vendor/slang`, no `SLANG_VERSION.lock`.

## Target architecture

1. **Authoring.** Shaders are Slang (`.slang`), single-source, multi-entry. (Slang is an HLSL
   superset; GLSL is not a Slang input, so the 37 GLSL shaders are rewritten — see Phasing.)
2. **Compile.** Vendored `slangc` (pinned at `tools/build/vendor/slang`, `SLANG_VERSION.lock` with
   upstream commit) compiles each `.slang` to the per-backend native blob: SPIR-V (Vulkan), MSL
   (Metal), DXIL (D3D12). Plus reflection JSON (bindings, vertex inputs, push-constant size,
   spec-constants).
3. **Bundle.** One per-backend container per shader: blob + reflection + Slang-version key. The
   platform TU carries only its backend's blob (§6.4). For the demos this is a generated
   `*_bundle.h` (or `.msl.h` / `.spv.h`) the app embeds — same committed-artifact shape as today's
   `_spv.h`, but generated by slangc and now per-backend.
4. **Load.** `shader_create_from_bytecode` extended to carry a **target + blob** (not SPIR-V-only):
   `{ target ∈ SPIRV|MSL|DXIL, vertex_blob, fragment_blob/compute_blob, entry names, reflection }`.
   The backend consumes its native target; `caps.shader.bytecode_passthrough.<target>` advertises
   what it accepts (§6.4 P2 peer).
5. **Backend lowering (Metal, the unblock).**
   - `shader_create_from_bytecode(MSL)` → `newLibraryWithSource:` (or `newLibraryWithData:` for
     precompiled `.metallib`) → retain the `MTLFunction`s (via the U-bridged `void*` ownership from
     the ARC fix).
   - `pipeline_create` → `MTLRenderPipelineDescriptor` (vertex+fragment functions, color/depth
     formats from the pass, vertex descriptor from reflection) → `MTLRenderPipelineState`.
   - `cmd_bind_pipeline` / `cmd_bind_vertex_buffer` / `cmd_draw[_indexed]` → encoder
     `setRenderPipelineState:` / `setVertexBuffer:` / `drawPrimitives:`.
   - Uniforms ride the now-fixed host-visible buffer path (`setVertexBuffer`/`setFragmentBuffer`).

## API delta

- `Mel_Gpu_Shader_Bytecode_Opt` gains a `target` and renames `spirv_*` to neutral `vertex_blob` /
  `fragment_blob` (+ sizes), keeping a SPIR-V-target default so existing call sites migrate
  mechanically. Compute analog likewise.
- New `caps.shader.bytecode_passthrough.{spirv,msl,dxil,wgsl}` bools (U4).
- Bundle loader `mel_gpu_shader_create_from_bundle(...)` is the Slang-convenience peer (later phase).

## Phasing (no-prerequisite root first)

- **P0 — ARC ownership fix (done, verified).** Prerequisite: Metal resources must survive. Landed,
  `gpu-resources` suite proves it under metal+vulkan.
- **P1 — Triangle proof on Metal (no-prereq root).** Vendor `slangc`; author `triangle.slang`;
  compile to MSL + SPIR-V; extend `shader_create_from_bytecode` with target/blob; implement the
  Metal MSL→library→render-pipeline→draw path. Outcome: the triangle renders under `--gpu=metal`,
  identically under `--gpu=vulkan`. This proves the whole chain end-to-end on the simplest screen.
- **P2 — Build integration.** Decide how `.slang` compiles in the repo (see Open decisions D2).
- **P3 — Reflection-driven layouts + bundle format.** Replace per-demo hand layout with Slang
  reflection; per-backend bundle container + Slang-version cache key.
- **P4 — Migrate the remaining 36 shaders** GLSL→Slang; the 20 hello-gpu screens render on Metal.
- **P5 — D3D12 DXIL target + compute + multi-entry + spec-constants + hot reload + runtime-compile
  opt-in** per §6.4.

## Open decisions (for iteration — Gabbo)

- **D1 Slang acquisition.** Vendor a pinned prebuilt `slangc` per host (macOS arm64 to start) under
  `tools/build/vendor/slang` + `SLANG_VERSION.lock`, per §6.4. (Recommended.) Alternative: link
  libslang for runtime compile (heavier, app-opt-in per §6.4 — a later phase, not P1).
- **D2 Build integration (blocking — CLAUDE.md halts on codegen).** Either (a) register a real
  build codegen pass that runs `slangc` during `nob build` (CLAUDE.md: pass registration is
  undocumented — needs Gabbo), or (b) a standalone regen tool (`nob shaders` / a script) that
  regenerates committed per-backend bundle headers, matching today's committed-`_spv.h` model. (b)
  is lower-risk and unblocks P1 without touching the codegen machinery.
- **D3 Migration scope.** Incremental (triangle first, then roll out) — recommended — vs big-bang
  rewrite of all 37 at once.
- **D4 Reflection source.** Consume Slang's emitted reflection (recommended; single source of truth,
  §6.4) vs keep per-demo hand-declared layouts through P4.

## Out of scope (here)

Bindless `melody.binding` mixin, ray/mesh/work-graph stages, LinAlg, pipeline-binary cache, hot
reload, runtime compile — all §6.4/§6.5 follow-ons after the demos render.
